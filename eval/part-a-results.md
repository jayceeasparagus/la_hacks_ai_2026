# Part A verification and evidence checkpoint

Validated on 2026-10-17 using Python 3.12.14, Pydantic 2.14.0, NumPy 2.3.5 and
OpenCV 5.0.0. The project supports Python 3.11+; 3.11 was not separately tested.

All **71 automated tests pass**. The earlier temporal suite remains passing.
New tests cover cached and uncertain verdicts, malformed-result retry, timeouts,
bounded queues, shared start-rate limiting, best-crop selection, ID recovery,
camera isolation, session reset, JPEG/MP4 decoding, encoding failure, review-safe
evidence patches and paused/EOF result collection.

## Saved-video CLI checks

Both inputs were generated by `engine.demo_recording` and are visibly labeled
synthetic. Tracks were written to JSONL, read back through the approved model,
and replayed alongside decoded video. Verifier answers were explicitly canned.

All expected images were reopened and all expected videos decoded successfully.
The exit JPEG was also visually inspected for its object box, camera/source
timestamp and synthetic label. Entrance clips are one second long because only
one second of history exists when those rules first become eligible.

## Reproduction

Install `backend/app/requirements.txt` into a Python 3.11+ environment. From
`backend/` run:

```sh
python -B -m unittest discover -v
python -B -m engine.demo_recording ../eval/generated/part_a
python -B -m engine.clip_replay \
  ../eval/generated/part_a/exit.mp4 \
  ../eval/generated/part_a/exit.tracks.jsonl \
  --config ../eval/generated/part_a/config.json \
  --evidence ../eval/generated/part_a/exit-evidence
```

For the three entrance cases, substitute `entrance` for `exit` in the video and
track filenames, use a separate evidence directory, and select respectively:

- `--stub-bag opaque --stub-camera professional`
- `--stub-bag clear --stub-camera ordinary`
- `--stub-bag unclear --stub-camera unclear`

Generated inputs, clips, images and result JSONL stay under ignored
`eval/generated/`; they are reproducible test artifacts, not source commits.

## Limits of these results

This validates Person 4's engine, scheduling, data flow and evidence-writing
behavior. No detector or Gemini API participated, and no real-camera FPS,
classification accuracy, full-pipeline false-alert rate or live latency is claimed.
The application still needs storage, serving of `/evidence`, WebSocket broadcast,
camera lifecycle handling and adapters to teammates' current module interfaces.
The default stub requests manual review; it does not infer transparency or camera
type. Real verification is an explicitly injected Person 2 callable.
